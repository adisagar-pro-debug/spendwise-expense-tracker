# Product outcomes

- [x] **Import multiple bank statements into one analysis workspace.** Users can upload multiple statements for the same workspace in CSV, TSV, XLS, XLSX, or text-based PDF format (up to 20 MB per file; PDF limited to 200 pages per file). Parse in the browser, normalize dates, descriptions, amounts, income/expenses, currency, and source statement, then analyze after import. Show file status, validation, skipped-row and extraction warnings, and sample rows before commit. Do not invent missing transaction values. For PDFs with labeled debit/credit and running-balance columns, read transaction amounts from their labeled debit/credit cells, exclude the running balance from transaction amounts, and associate wrapped narration lines with the dated transaction row. Preserve a dated amount as a flagged “Unlabeled transaction” if no narration can be associated. Use labeled statement currency and infer date order from unambiguous dates where available. If a positive-only amount or numeric date remains ambiguous, let the user choose its meaning/order in the preview. Read the first worksheet only and disclose that limitation. Scanned/image-only PDFs are unsupported. Statement files are never uploaded or stored; transaction rows stay in tab memory and clear on refresh/close.

- [x] **Categorize transactions and resolve uncertain classifications.** Suggest categories from explainable merchant/keyword rules and saved user corrections; show confidence and classification method. If classification remains unresolved, mark the transaction Unknown. Do not show an external Google Research button or send transaction details to a search provider. Let the user assign or correct a category manually in the import preview or ledger, then save merchant/category corrections in this browser so later imports reuse them.

- [x] **Analyze spending in the dashboard.** Provide spending, income, net cash flow, category breakdowns, trends over time, and top merchants. Include This month, Last month, Last 3 months, and Last 6 months ranges. Keep currency totals separate; do not apply exchange-rate conversion.

- [x] **Search, filter, and read the transaction ledger.** Offer searchable and filterable transaction views by date, statement/bank, category, merchant, amount, and classification status. Render filtered results using selectable 25-, 50-, or 100-row pages, reset pagination when filters change, and show the current row range and page controls. Use high-contrast, readable table text and filter controls; support horizontal scrolling rather than shrinking transaction text on narrow screens.

- [x] **Prevent duplicate uploads from distorting analysis.** Detect likely duplicates across overlapping/repeated imports, exclude candidates from totals by default, let users reverse the decision for genuine repeated transactions, and recalculate duplicate status when a source statement is removed.
